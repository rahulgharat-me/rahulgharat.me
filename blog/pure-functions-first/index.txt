10:T946,<p>Every app has a small piece of logic that everything else depends on. In a habit tracker it's "is this day perfect, and how long is the streak". In a billing system it's how an invoice gets calculated. In the workflow engine we built at DronaHQ it was deciding which step runs next.</p>
<p>That logic tends to end up wherever it was first needed. A bit in the SQL query, a bit in an API handler, a bit in a React component that formats the result. It works, but you can't test it without standing up the whole thing, so it doesn't get tested, so nobody wants to touch it.</p>
<p>On Ember I pulled the streak and completion-rate rules into one module, <code>streaks.py</code>. Each habit's history gets loaded into a frozen dataclass, and everything else is plain functions over it. They don't touch the database or know what a request is.</p>
<pre><code class="language-python">@dataclass(frozen=True)
class HabitHistory:
    habit_id: int
    start_date: date
    end_date: date | None
    completed_days: frozenset[date]
    skip_weekdays: frozenset[int] = frozenset()
    skip_dates: frozenset[date] = frozenset()

    def is_active(self, day: date) -> bool:
        return (
            self.is_tracked(day)
            and day.weekday() not in self.skip_weekdays
            and day not in self.skip_dates
        )
</code></pre>
<p>The rules are written out in plain English in the module docstring too, so the code and the explanation sit next to each other.</p>
<p>Once the rules were in one place, the tests were easy to write, and they're the cases I actually worry about:</p>
<ul>
<li>A habit started on a Wednesday shouldn't make Monday imperfect.</li>
<li>An archived habit stops counting from the day it was archived, not before.</li>
<li>An unfinished today doesn't break the streak.</li>
<li>A day with nothing scheduled is skipped, not counted as perfect.</li>
</ul>
<p>Each one is a few lines of test with no fixtures and no database. They run in milliseconds, so I run them all the time.</p>
<p>The database layer gets simpler too. It loads rows and passes them in. If the rules change, I change one module and the tests tell me what broke.</p>
<p>None of this is new. It's "functional core, imperative shell", and people have been saying it for years. But on a side project, where nobody makes you do it, I can see clearly how much time it saved.</p>
