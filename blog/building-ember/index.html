I built a habit tracker because none of them understood days off

2026-10-27

I've tried a lot of habit apps. They all had the same problem for me. I don't work out on Sundays, on purpose, and every app treated Sunday as a failure. Break the streak, or lie and tick the box. After a while you stop trusting the number, and once you stop trusting the number the app is useless.

So I built my own. It's called Ember and the code is on GitHub.

The rules

Most of the work went into getting the streak rules right, not the UI. What I ended up with:

  • A perfect day is a day where every habit scheduled for that day is done.
  • The streak is the run of perfect days ending today.
  • Today doesn't count against you until it's over. Opening the app at 9am shouldn't show a broken streak.
  • Days off (weekly, or one-off like a holiday) are skipped. They don't break the streak and they don't extend it either.
  • A new habit only counts from its start date, so adding one doesn't rewrite history.
  • Archiving a habit stops it counting from that day, but keeps its past.

Archiving is the subtle one. If you just drop archived habits from the calculation, old days that were partial suddenly look perfect. So an archived habit gets an end date, and it's tracked up to that day and not after.

The stack

Next.js and TypeScript for the frontend, FastAPI with SQLAlchemy and SQLite on the back. SQLite is plenty for this. The whole database is one file, which makes backups a cp.

I put the frontend in front of everything: the browser only talks to Next.js, and Next.js proxies /api to FastAPI on localhost. I wrote a separate post about why I like that setup.

Sign-in is GitHub only. I didn't want to store passwords for a side project. It's invite-only too: anyone can ask for access, and I get a notification and approve it from inside the app.

What I'd tell myself at the start

Write the streak logic first, as plain functions with tests, before any screens. I did it the other way round and ended up untangling date math out of React components. Once it was moved into its own module with tests for the weird cases (leap years, a habit started mid-week, a day off on today), the rest of the app was easy.

The full rules and the feature list are on the about page.
